# Office Demo Update - 23 October 2026

This is the reproducible source delivery for the office evaluation, not a
production recognition-accuracy claim. Use SCRFD-2.5G and the existing three-model
bundle. No additional detector or model download is required for this update.

## What Changed

- Recent recognitions replace Unknown rows below each stream. All active tracks
  and debugging crops remain inside expandable Track evidence.
- Up to 20 browser-session entries per camera retain names, match scores and
  first/last-seen times. Repeated observations update a row. Tentative, Confirmed,
  Head-tracked, Not revalidated and Earlier match are distinguished.
- Clickable snapshots show observed camera crops, not enrolled portraits. Better
  quality crops can replace them. They remain in bounded browser memory, are
  released on removal/reset, and are never enrolled by this feature.
- Reset all settings restores the full, backend-defined 11-control Office Demo
  preset after confirmation and saves it persistently. It does not delete cameras
  or people. Existing saved settings remain in effect during an upgrade.
- The non-root Docker runtime can read the shared vision package even if the
  source checkout had restrictive permissions.

These cards are frontend recognition history, not a durable alarm/event store or
a new alert webhook. They do not guarantee every brief match is captured between
dashboard polls, and they reset on reload or changes of evaluation settings.

## Adopted Evaluation Settings

| Setting | Value |
| --- | --- |
| Match threshold / margin | 0.30 / 0.06 |
| Minimum face width / query quality | 20 px / 49 |
| Analysis rate / recognition rate | 10 FPS / 1 Hz |
| Admission threshold / margin | 0.68 / 0.10 |
| Adaptation / single-reference mode | Review / Review |
| Face detection | Full frame, SCRFD-2.5G |

Automatic admission remains locked by default. Registration retains strict
quality checks and at least 70-pixel native faces. One-photo review proposals
also retain their stricter 80-pixel and registered-reference evidence gates.
These query settings may allow false identity matches; evaluate known positive
and negative examples before production use. Display-on/off false alarms from
brightness/saturation rules are a separate pipeline and investigation.

## Update an Existing Ubuntu/NVIDIA Installation

Use the same private runtime, model paths and Compose project as before. Do not
create a new gallery or delete a volume to update the UI. Review the cold-backup
instructions in section 13 of [the runbook](README.md#13-persistence-backup-and-restore)
first. Restore the original installation exports, including custom port, GPU ID
and project name, before running any Compose commands.

From your existing repository checkout:

```bash
git status --short
git fetch origin
git switch codex/office-face-enrollment-multicam
git pull --ff-only origin codex/office-face-enrollment-multicam
git rev-parse HEAD
cd face_id_poc
```

If Git reports local modifications, stop and preserve/review them; do not use
`reset --hard`. Older office deployments may have an uncommitted vision-package
permissions fix in Dockerfile, now included in this release. Preserve that file
before resolving its overlap with the incoming update. The branch is usable
before merge; do not assume `main` contains it until the PR is merged.

With the **same absolute** `OFFICE_RUNTIME_DIR`, `OFFICE_MODELS_DIR` and
`OFFICE_PROJECT_NAME` already exported for this installation:

```bash
export OFFICE_IMAGE=camex-office-demo:office-20261023
python3 office_demo/scripts/build_image.py --tag "$OFFICE_IMAGE"
bash office_demo/scripts/office_stack.sh config
bash office_demo/scripts/office_stack.sh up
bash office_demo/scripts/office_stack.sh doctor
curl --fail --silent --show-error --noproxy '*' \
  "http://127.0.0.1:${OFFICE_APP_PORT:-9170}/api/health"
```

Pulling Git alone is not enough: the app serves the files embedded in its image.
Rebuild and recreate it as above, then refresh the browser. The health response
must report `office-evaluation-20261023` and `ready: true` with no engine/index
errors. Camera records are retained but load stopped after app recreation;
review their addresses privately and press Start all. No re-enrollment is needed.

Open Diagnostics and confirm the existing saved values. To adopt the exact
office preset, click **Reset all settings**, inspect the complete confirmation
and approve it. Verify all 11 controls, then verify persistence after an app
restart. Do not confuse Reset with removing cameras or deleting people.

## Fresh Installation and Test Checklist

For a different Ubuntu machine, follow the [full runbook](README.md) from section
1: native prerequisites, sparse clone, private paths, existing model-bundle import,
build and CUDA doctor. Then enroll your own authorized single photos or named
folders/ZIP, add your own RTSP addresses privately, and start the feeds.

- Verify all three models execute on CUDA, not only that CUDA is installed.
- Check the expected gallery, single/bulk preview/commit and existing references.
- Check fresh overlays, named cards and the actual observed crop in its enlarged
  preview; keep tentative results visibly tentative.
- Exercise reset cancellation and all 11 values; confirm cameras/photos survive.
- Save custom settings, recreate the app and confirm they are not overwritten.
- Check ambiguous/unknown faces and false matches; UI confirmation is an
  algorithm state, not proof of a correct real-world identity.

No private photos, camera addresses, credentials, databases, weights or recorded
office video are part of the source update. Preserve the previous image tag and
private backup for rollback. This release changes presentation and preset/reset
behavior; it does not add a new recognition model or claim improved accuracy.
